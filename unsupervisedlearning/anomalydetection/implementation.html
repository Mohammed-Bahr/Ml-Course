3. أهم function: gaussian_p()

الكود:

def gaussian_p(X, mu, var, eps=1e-12):
    var = np.maximum(var, eps)

    log_p = (
        -0.5 * np.log(2 * np.pi * var)
        -0.5 * ((X - mu) ** 2) / var
    )

    return np.exp(np.sum(log_p, axis=1))

دي implementation للمعادلة:

خلينا نفكها.

8. طب إيه فايدة gaussian_log_p()؟

الكود الثاني:

def gaussian_log_p(X, mu, var, eps=1e-12):
    var = np.maximum(var, eps)
    log_p = (
        -0.5 * np.log(2 * np.pi * var)
        -0.5 * ((X - mu) ** 2) / var
    )
    return np.sum(log_p, axis=1)

الفرق الوحيد:
| Function | ترجع إيه؟ |
| :--- | :--- |
| gaussian_p | |
| gaussian_log_p | |

متى نستخدم الـLog version؟

ده مفيد جدًا لو عندك features كثيرة. بدل ما تعمل p < epsilon، تقدر تعمل log_p < np.log(epsilon). وده يتجنب إن p تتحول إلى 0.0 بسبب underflow.

9. إيه قصة np.maximum(var, eps)؟

var = np.maximum(var, eps)

افترض feature معينة كل قيمها: [5, 5, 5, 5, 5]
يبقى:
وساعتها Gaussian فيها و np.log(var) هيعمل مشاكل (Division by zero / Log of zero).

فنعمل:

var = np.maximum(var, 1e-12)

لو variance أقل من ، اعتبرها .

دي numerical safety، مش جزء أساسي من algorithm نفسه.

10. select_threshold() وإيه هو epsilon؟

دي أهم function بعد gaussian_p.
إحنا عندنا p_cv مثلاً:

normal:  0.42, 0.31, 0.51, 0.27
anomaly: 0.00001, 0.00003, 0.000001

لاحظ:

  • normal relatively high
  • anomaly very low

وده أساس algorithm:

epsilon هو الـdecision boundary.
مثلاً: epsilon = 0.001

  • anomaly
  • normal

المشكلة: نختار epsilon كام؟ وهنا يأتي دور select_threshold().

11. ليه بنستخدم CV set؟

  • Training data: normal only
  • CV data: normal + anomalies
  • Test data: final evaluation (unseen)

وبالتالي نقدر نجرب thresholds ونشوف أي واحد يعطي أفضل detection.

12. الـloop بتاع epsilon

for eps in np.linspace(p_val.min(), p_val.max(), n_steps):

يعني: جرّب 1000 قيمة مختلفة للـepsilon بين أصغر وأكبر probability في الـCV set.

Prediction لكل epsilon

pred = p_val < eps

لو p_val = [0.5, 0.3, 0.0001] و eps = 0.001
يبقى: [False, False, True] (أي: normal, normal, anomaly).

13. TP / FP / FN والـMetrics

الكود:

tp = np.sum(pred & y_val)
fp = np.sum(pred & ~y_val)
fn = np.sum(~pred & y_val)
Metric Model Prediction Ground Truth (y_val) المعنى
TP True (Anomaly) True (Anomaly) اكتشفناه صح
FP True (Anomaly) False (Normal) فزّعنا فاضي
FN False (Normal) True (Anomaly) فاتنا الـAnomaly

Precision

prec = tp / (tp + fp)

من كل حاجة أنا قلت إنها anomaly، كام واحدة فعلًا anomaly؟

Recall

rec = tp / (tp + fn)

من كل الـanomalies الموجودة فعلًا، أنا اكتشفت كام؟

F1 Score

f1 = 2 * prec * rec / (prec + rec)
$$
$$
F_1 = \frac{2PR}{P+R}
$$
الـF1 يحاول يوازن بين Precision و Recall، والنوت تستخدم F1 لاختيار الـepsilon.

الخلاصة الذهنية

الكود كله ممكن تختصره ذهنيًا إلى 4 عمليات:

  1. ① Learn normal

    mu, var = estimate_gaussian(X_train)

  2. ② Score

    p = gaussian_p(X, mu, var)


    (كلما كان الـpoint بعيدًا عن الـnormal distribution، غالبًا )

  3. ③ Choose boundary

    epsilon, f1 = select_threshold(y_cv, p_cv)


    (والـ يتم اختياره باستخدام الـlabeled CV set)

  4. ④ Predict

    y_pred = predict(X_test, mu, var, epsilon)

    new X calculate p(x) p(x) < epsilon ? Yes: anomaly / No: normal

الـInsight النهائية

وأهم insight في الـimplementation كلها: الـmodel نفسه لا يتعلم "anomaly". هو يتعلم distribution of normal data فقط؛ الـCV labels تدخل لاحقًا لاختيار الـdecision threshold وتقييم الأداء.
