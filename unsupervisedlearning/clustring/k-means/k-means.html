K-means is an unsupervised learning algorithm you give it unlabeled data points and ask it to group them into clusters. There's no "correct answer" provided; the algorithm just organizes the data based on proximity.

It does this by repeating two simple steps forever until nothing changes:

  1. Cluster assignments : Assign color each point by whichever cluster (1 to ) center (centroid) it's closest to.
  2. Cluster centroids : Update move each centroid to the average position of the points assigned to it.

That's it. Repeat those two steps and the centroids "settle" into good cluster centers.

The Algorithm, Formally

Step 0 Initialize: Randomly pick cluster centroids .
In practice, this is done by picking random training examples and using their locations as the initial centroids (not arbitrary random points).

Step 1 Assign points to clusters: For every training example , find the closest centroid:

  • For each point , find the centroid it's closest to and assign it there.
    minimizing the squared distance gives the same assignment as minimizing the distance itself (squaring is monotonic for non-negative values), and squared distance is cheaper to compute no square root needed.
  • This is why implementations use squared distance everywhere.

Step 2 Move the centroids: For each cluster , recompute its centroid as the mean of all points currently assigned to it:

where is the set of indices of Training points that assigned to cluster .

Repeat Steps 1–2 until assignments stop changing → converged.

Edge case: empty cluster

If no points get assigned to some cluster , the mean of zero points is undefined. Standard handling:

  • Most common: eliminate that cluster (end up with clusters), or
  • Reinitialize that centroid randomly and hope it attracts points next round.

A quick code sketch

import numpy as np

def kmeans(X, K, n_iters=100):
    # Step 0: init centroids = K random training examples
    idx = np.random.choice(len(X), K, replace=False)
    centroids = X[idx]

    for _ in range(n_iters):
        # Step 1: assign each point to nearest centroid
        dists = np.linalg.norm(X[:, None] - centroids[None, :], axis=2)  # (m, K)
        c = np.argmin(dists, axis=1)  # cluster assignment per point

        # Step 2: move centroids to mean of assigned points
        new_centroids = np.array([
            X[c == k].mean(axis=0) if np.any(c == k) else centroids[k]
            for k in range(K)
        ])

        if np.allclose(new_centroids, centroids):
            break  # converged
        centroids = new_centroids

    return c, centroids

What Is K-Means Actually Optimizing? (The Cost Function)

Just like supervised learning uses gradient descent to minimize a cost function, K-means is secretly minimizing a cost function too it's just optimized differently (not via gradient descent).

  • = squared distance from point to its cluster's center.
  • The sum averages this over all points.

Intuition: is the average squared distance between points and "their" centroid.
- Small = points are tightly packed around their centroids = good clustering.
K-means goal is to find assignments and centroid locations that minimize .

Why the two steps minimize

  • Step 1 (assignment) minimizes with respect to , holding the centroids fixed.
    • This is obvious: for a fixed point , the term is smallest when you assign the point to whichever centroid is nearest.
    • There's no other choice that could do better.
  • Step 2 (move centroids) minimizes with respect to , holding assignments fixed.
    • This is a small calculus fact: the mean minimizes the sum of squared distances.
    • For a set of points, is exactly the value that minimizes .

Since every single step of the algorithm can only decrease (or keep equal) the cost , this gives two important guarantees:

  1. K-means is guaranteed to converge is monotonically non-increasing, and it's bounded below by 0, so it must stop decreasing eventually.
  2. You have a bug if ever increases. This is a genuinely useful debugging check when implementing K-means yourself.
  3. You can use to detect convergence: once stops changing between iterations (or the decrease becomes negligibly small), you can stop.

Random Initialization Why and How to Do It Multiple Times

Constraint: Always choose (you can't have more clusters than data points).

Standard initialization method: randomly pick training examples from the dataset itself and use those exact points as the initial centroids not arbitrary random locations in space.

The local minima problem

K-means cost function is not convex depending on where you randomly initialize the centroids, the algorithm can converge to a local minimum that's a much worse clustering than what's actually possible on the data.

Summary: Different initializations lead to different final clusterings, and some are really bad.

  • A lucky init finds three clean clusters → small
  • An unlucky init puts two centroids in one blob → K-means splits that blob awkwardly → larger

These are local minima of .

The fix: multiple random restarts

best = None
for r in range(R):              # R = 50–1000, commonly ~100
    μ = random K training examples
    c, μ = kmeans(X, μ)         # run to convergence
    J = distortion(X, c, μ)
    if best is None or J < best.J:
        best = (c, μ, J)

Keep the clustering with the lowest final distortion . Since directly measures cluster tightness, this picks the best of your runs.

Practical notes:

  • Diminishing returns: beyond ~1000 restarts you mostly burn compute.
  • When does this matter most? With small (like 2–10), restarts help a lot. With large (hundreds), a single run is often already near-optimal because there's "nowhere to get stuck" restarts matter less.
  • Cost: each restart runs full K-means, so it's the runtime. For big datasets, people often cap restarts (e.g., n_init=10 in scikit-learn's default).
Important: you can only use to compare different runs of K-means for the same K. You must not use to choose itself see below.

Choosing the Number of Clusters, K

The most common method: randomly pick actual training examples and set to their locations. (The course's earlier illustrations used arbitrary random points instead, purely for clarity.)

Always choose you can't have more clusters than data points (each cluster needs at least one point to be meaningful).

Why you can't just minimize over

If you chose by minimizing the cost function, you'd almost always end up picking the largest possible because adding more clusters (in the extreme, one cluster per point) always drives down.
This gives you overfitting-like behavior and isn't a meaningful choice of . Never pick this way.

Method 1: The Elbow Method (mentioned, but not generally recommended)

  • Run K-means for a range of values (1, 2, 3, ...) and plot vs. .
  • decreases as increases (as explained above). Sometimes the curve has a visible "elbow" a point where the decrease sharply flattens and you'd pick that .
  • Caveat (explicitly stated in the lecture): In many real applications, the -vs- curve decreases smoothly with no clear elbow, making this method unreliable. It's mentioned because you'll see it referenced, not because it's the recommended default.

Method 2: Choose K based on downstream purpose (recommended in practice)

Choose by how well the clustering serves what you're going to do with it.

Since we're usually running K-means to use the clusters for something else, evaluate different values of based on how well they serve that downstream task not based on alone.

Example t-shirt sizing:
  • → small/medium/large: simpler manufacturing, less cost, looser fit.
  • → XS/S/M/L/XL: better fit, but more manufacturing/shipping cost.
  • Decision: run K-means for both, then pick based on the business trade-off (fit quality vs. cost), not based on which has lower distortion.
