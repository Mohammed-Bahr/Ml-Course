Rows vs. columns

Option Normalizes Helps with

What we did above normalizes each row (each item, averaged over users).
The alternative is normalizing each column (each user, averaged over their rated item):

  • Row normalization (what we did) helps when there's a new user with no/few ratings. ← This is the common, important case.
  • Column normalization would help when there's a new item with no ratings.

But Andrew argues Column normalization matters less: if nobody has rated a movie, you shouldn't be aggressively recommending it anyway.

Practical takeaway: normalize rows (per-item means) for a standard item recommender.

Code

import numpy as np

def normalize_ratings(Y, R):
    """Y, R: shape (num_items, num_users). Returns Ynorm, mu."""
    counts = np.maximum(R.sum(axis=1), 1)          # avoid divide-by-zero for unrated items
    mu = (Y * R).sum(axis=1) / counts              # per-item mean over rated entries only
    Ynorm = (Y - mu[:, None]) * R                  # subtract only where a rating exists
    return Ynorm, mu

* R matters: it zeroes out unrated entries, so they aren't turned into fake ratings like .

2. Implementing Collaborative Filtering in TensorFlow

Why TensorFlow?

TensorFlow is not only for neural networks. Its key feature here is automatic differentiation (autodiff). You write the cost function , and TensorFlow computes the derivatives for you, with no calculus by hand.

Terminology: Auto Diff is the technique. Autograd is the name of one specific package, though people often use it loosely for the same idea. PyTorch also supports autodiff.

Warm-up: gradient descent on a toy cost

Gradient descent update:

import tensorflow as tf

w = tf.Variable(3.0)      # tf.Variable => "this is a parameter to optimize"
x, y, alpha = 1.0, 1.0, 0.01

for it in range(30):
    with tf.GradientTape() as tape:       # records operations for differentiation
        fwb = w * x
        costJ = (fwb - y) ** 2

    [dJdw] = tape.gradient(costJ, [w])    # dJ/dw computed automatically
    w.assign_add(-alpha * dJdw)           # w = w - alpha * dJdw

tape.gradient(costJ, [w]) Returns with respect to the listed variables
w.assign_add(...) tf.Variables need special in-place updates, so you can't write w = w - ... normally

Collaborative filtering with autodiff and Adam

Because gradients come for free, you're not limited to plain gradient descent. You can use Adam, which adapts the step size per parameter and usually converges faster.

import tensorflow as tf
from tensorflow import keras

# Y, R: (num_items, num_users); Ynorm from the normalization step
num_items, num_users = Y.shape
num_features = 100

# Random init: X, W, b are ALL learned, so they can't all start at 0
W = tf.Variable(tf.random.normal((num_users,  num_features), dtype=tf.float64), name='W')
X = tf.Variable(tf.random.normal((num_items, num_features), dtype=tf.float64), name='X')
b = tf.Variable(tf.random.normal((1, num_users),             dtype=tf.float64), name='b')

optimizer = keras.optimizers.Adam(learning_rate=1e-1)

def cofi_cost_func(X, W, b, Ynorm, R, lambda_):
    pred_err = (tf.linalg.matmul(X, tf.transpose(W)) + b - Ynorm) * R   # mask unrated
    J = 0.5 * tf.reduce_sum(pred_err ** 2) \
        + (lambda_ / 2) * (tf.reduce_sum(X ** 2) + tf.reduce_sum(W ** 2))
    return J

lambda_ = 1.0
for it in range(200):
    with tf.GradientTape() as tape:
        cost_value = cofi_cost_func(X, W, b, Ynorm, R, lambda_)

    grads = tape.gradient(cost_value, [X, W, b])          # dJ/dX, dJ/dW, dJ/db
    optimizer.apply_gradients(zip(grads, [X, W, b]))      # Adam update

How this maps to the math:

  • X @ W.T + b computes all predictions at once. Entry is . Shapes: , where broadcasts across rows.
  • * R zeroes out unrated entries, which implements .
  • The first term is , and the second is the two regularization terms.
  • zip(grads, [X, W, b]) pairs each gradient with its variable. The transcript describes it as rearranging the numbers into the ordering apply_gradients expects.
  • Random initialization is required because is learned too. If NewUserrything started at zero, all features would get identical gradients and nNewUserr differentiate.

Why not Dense + compile + fit?

The usual Keras recipe assumes a chain of standard layers mapping inputs to outputs. Collaborative filtering doesn't fit that:

  • The features are parameters, not inputs.
  • The cost is a masked sum over a ratings matrix, not a per-example loss over pairs.

So you write the cost yourself and let TensorFlow handle derivatives and optimization. This "custom cost + GradientTape" pattern works for many algorithms beyond neural nets.

3. Finding Related Items, and Limitations

Finding related items Using Learned Features

The application: When a user views a book/item on a shopping site, show "similar items." Collaborative filtering gives you this almost for free.

The key insight: To find items similar to item , we calculate the squared Euclidean distance between and every other item's feature vector .

Therefore, items with similar feature vectors are similar items.

The similarity measure squared Euclidean distance:

  • Each term penalizes disagreement on feature .
  • Squaring makes everything non-negative (mismatches accumulate) and is the standard squared distance between vectors

The practical recipe:

  1. View item 's feature vector
  2. Compute for every other item
  3. Take the 5 or 10 items with the smallest distance → these are your "related items"
def related_items(X, i, k=10):
    dist = np.sum((X - X[i]) ** 2, axis=1)   # squared distance to `NewUser`ry item
    dist[i] = np.inf                         # exclude the item itself (distance 0)
    return np.argsort(dist)[:k]
This is just a k-nearest-neighbors search in the learned feature space. Cheap and effective, and it becomes a building block for the more advanced recommender coming later in the course.

Limitations of collaborative filtering

1. Cold start problem

  • New items with few or no ratings can't be ranked well.
  • New users with few ratings get inaccurate recommendations.
  • Mean normalization helps a lot, but better strategies exist.

2. No natural way to use side information: Collaborative filtering only sees the ratings matrix. It has no built-in way to use:

  • Item info: genre, stars, studio, budget.
  • User info: age, gender, location, stated genre preferences, IP address (which hints at location), mobile vs. desktop, and browser (Chrome, Firefox, Safari, and Edge users behave measurably differently).

These cues can correlate with preferences, especially for cold-start users. Content-based filtering, coming in the next video, is designed to use them, and it is widely used in commercial systems.
