1. What is reinforcement learning?

Core idea: you don't tell the algorithm what action is correct for each input. You specify a reward function that says when it's doing well or badly, and the algorithm figures out the actions itself.

Why not supervised learning? For the helicopter, supervised learning would need labeled pairs .
But at every moment there's no single "right" action (tilt a little or a lot? more thrust or less?), so that dataset can't be built. RL only needs a score for outcomes.

Supervised learning Reinforcement learning
Needs the correct output for every input Needs only a reward signal
You specify how (via labeled examples) You specify what (via reward)
The dog-training analogy: you can't demonstrate to a puppy what to do. You let it act, say "good dog" or "bad dog," and it learns to do more of the good. The same holds for a helicopter (+1 per second flying well, −1000 for a crash) or a robot dog (reward for moving toward the goal).

Applications mentioned: helicopter aerobatics, legged-robot locomotion, lunar lander (this week's lab), factory optimization, stock execution (e.g., selling 1M shares over several days without moving the price), and games (checkers, chess, bridge, Go, video games).

Caveat from the lecture: RL is far less used commercially than supervised learning, but it's a pillar of ML with active research.

2. The formalism via the Mars rover

It is adapted from Stanford professor Emma Brunskill's example

Setup: 6 positions in a row (states 1–6). The rover starts at state 4.

Concept Symbol In the rover example
State Position, 1–6
Action Go left / go right
Reward 100 at state 1, 40 at state 6, 0 at states 2–5
Next state Where you land after the action
Terminal state States 1 and 6: you collect the reward, then the episode ends

Every step produces a tuple . These four things are what RL algorithms actually consume.

Details to note:
  • is the reward for the state you're in, not the one you're moving to. Starting at state 4 and going left, the reward of 0 belongs to state 4, not state 3.
  • State 1 is more valuable (100) but farther away, and state 6 is closer but worth less (40). This trade-off is what makes the problem interesting.
  • Wasteful paths are legal, e.g., right, right, then reverse left. The algorithm must learn to avoid them.

Comparing sequences of rewards needs a single number.
Rewards alone don't tell you if a sequence of actions was good; you need to aggregate them. But sooner rewards are usually more attractive than later ones.

Finance: is like the time value of money ($1 today > $1 later because of interest).

Negative rewards: discounting makes the agent want to postpone penalties. Owing $10 in a few years is better than owing it today. This is the desired behavior in finance, but keep it in mind when designing rewards.

4. Policy

A policy is a function from states to actions:

Example policy for the rover:
π(2) = left
π(3) = left
π(4) = left
π(5) = right

Candidate policies you might imagine: "go for the nearer reward," "always go for the larger reward," "go left unless one step from the smaller reward" each is just a different π.

The goal of reinforcement learning, stated formally:

Find the policy π that maximizes the expected return in every state.

(A side note from the lecture: "policy" isn't the most descriptive word "controller" might be more natural but it's the universally standard term.)

6. Markov Decision Process (MDP)

The formalism above is an MDP.

  • Markov property: the future depends only on the current state, not on how you got there.
  • Agent–environment loop: the agent picks action via , the environment changes, and the agent observes the new state and reward.

7. Code: computing returns for the Mars rover

This reproduces every number in the tables above.

import numpy as np

REWARDS  = np.array([100, 0, 0, 0, 0, 40], dtype=float)  # states 1..6 -> idx 0..5
TERMINAL = {0, 5}
LEFT, RIGHT = -1, +1

def compute_return(start, policy, gamma=0.5):
    """policy: array of actions, one per state (ignored at terminal states)."""
    s, G, discount = start, 0.0, 1.0
    while True:
        G += discount * REWARDS[s]        # collect R(s), weighted by gamma^t
        if s in TERMINAL:                 # episode ends after terminal reward
            return G
        s += policy[s]                    # deterministic transition: s' = s + a
        discount *= gamma

always_left  = [LEFT] * 6
always_right = [RIGHT] * 6
mixed        = [LEFT, LEFT, LEFT, LEFT, RIGHT, LEFT]  # right only in state 5

for name, pi in [("left", always_left), ("right", always_right), ("mixed", mixed)]:
    print(name, [compute_return(s, pi) for s in range(6)])
# left  [100.0, 50.0, 25.0, 12.5, 6.25, 40.0]
# right [100.0, 2.5, 5.0, 10.0, 20.0, 40.0]
# mixed [100.0, 50.0, 25.0, 12.5, 20.0, 40.0]

Since this is just brute-force evaluation of a fixed policy, the RL algorithms coming next will search for the best policy instead of you writing it by hand.

Key takeaways

  1. RL specifies what you want (rewards), not how to do it.
  2. A problem is defined by states, actions, rewards, , and solved by finding a policy .
  3. The return scores a whole trajectory, favoring sooner rewards.
  4. Different policies give different returns from the same state, so the goal is to find that maximizes it.
  5. All of this is an MDP, where the future depends only on the current state.
